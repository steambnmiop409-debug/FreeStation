## 2. ‘시간 지평’ 지표 (METR) [A]
- 정의: **사람 전문가가 걸리는 시간**으로 과제 길이를 재고, 모델이 **50% 성공률**로 완수하는 과제 길이를 그 모델의 시간 지평으로 정의. 약 **170개 과제**에 로지스틱 모델을 적합하고 모델 출시일에 대해 그린다.
- 결과: 2019–2025년 50% 시간 지평이 **지수적**으로 늘었고 **배가 시간은 약 7개월**. 개정판(v4)의 탐색적 분석으로는 2023–2025 증가율이 2019–2025보다 약 20% 빠르다.
- 값의 변화(판본 의존): v2에서 Claude 3.7 Sonnet 약 **50분**, v4에서 o3 약 **110분**. 저자들은 개선의 주된 이유를 신뢰성, 실수에 대한 적응, 논리 추론, 도구 사용 능력으로 본다.
- **한계/반론** [A]: 측정이 소프트웨어·연구 과제에 한정되어, 외삽의 현실적 읽기는 “소프트웨어 과제 1개월 지평”이지 “1개월짜리 AGI”가 아니다. 지수 증가라는 틀에 대안 가설을 제시한 2026년 연구와, 사람 소요 시간 주석 비용 문제를 줄이려는 BRIDGE가 있다.

## 3. 범용 에이전트의 초기 사례
- **Gato** [A]: 같은 가중치의 단일 네트워크가 Atari, 이미지 캡션, 채팅, 실제 로봇 팔로 블록 쌓기 등을 수행하며, 문맥에 따라 텍스트·관절 토크·버튼 입력 등을 출력한다. **604개 과제**로 학습했고, 시뮬레이션 제어 과제 중 **450개 이상**에서 전문가 점수의 50%를 넘는다. 1.2B 파라미터 디코더 전용 Transformer.
- **Voyager** [A]: 마인크래프트에서 기존 최고 대비 **고유 아이템 3.3배**, **이동 거리 2.3배**, 기술 트리 이정표를 **최대 15.3배 빠르게** 해제. 15.3배는 나무 단계에서의 값이며 시간이 아니라 *프롬프트 반복 횟수* 기준이다. 160회 반복에서 고유 아이템 63개, 다이아몬드 단계까지 해제한 것은 Voyager뿐이다.

## 4. 이 숫자들을 읽을 때의 함정
| 함정 | 근거 |
|---|---|
| **설정 의존** — 같은 벤치마크에서도 oracle 검색기 vs BM25, 수동 질의 vs 자동 에이전트, 평가기 버전에 따라 값이 달라진다 | SWE-bench 1.96% vs 4.8%; GAIA 수동 질의; WebArena Verified [A] |
| **오염·암기** — SWE-bench 성능이 암기를 반영할 수 있다는 문제 제기, 이를 줄이려는 Live/Pro/다국어 변형 | [A: 제목만] |
| **벤치마크 판본의 증식** — Verified, Live, Pro, Multi-SWE-bench 등 | [A: 제목만] |
| **인간 기준선의 정의** — GAIA 92%, WebArena 78.24%, OSWorld 72.36%는 각기 다른 인간 집단·절차 | [A] |
| **신뢰성 vs 평균 성공률** — τ-bench는 반복 시행 일관성(pass^k)을 따로 잰다 | [A] |
| **지표의 단일성** — 시간 지평은 소프트웨어·연구에 한정 | [A] |

## 5. 해석 [J]
1. **격차는 빠르게 줄었지만 벤치마크마다 속도가 다르다.** GAIA는 15%(수동 질의)에서 약 75%(상위 에이전트)로, OSWorld는 12.24%에서 38.1%로 움직였다 [A]. 다만 기준 시점·설정이 달라 *속도*를 정량 비교하는 것은 부적절하다.
2. **인간 대비 격차의 종류가 바뀐다.** 초기에는 *도구 사용 자체*의 실패(GUI 접지 등)가 지배적이었고, 시간 지평 분석은 *신뢰성·실수 복구*가 병목임을 시사한다 [A: 저자들의 귀인]. 이는 pass^k, 8시간 환경 같은 지표의 필요성을 뒷받침한다.
3. **벤치마크는 ‘포화’보다 ‘수명’이 문제.** SWE-bench는 1.96% → 12.5% → (여러 후속 시스템) 로 빠르게 소진되어 변형이 계속 만들어진다.
