# 심층 07. 추론 시 연산과 잠재 추론 — 더 오래 생각하기 vs 말하지 않고 생각하기

## 1. 토큰으로 생각하기: 연산을 어떻게 늘리는가
Snell 등은 두 방식을 분석한다 [A]:
1. **프로세스 기반 검증기(보상 모델)에 대한 탐색** (best-of-N, 빔, 룩어헤드 등 [K]).
2. **프롬프트마다 출력 분포를 추론 시에 적응**(순차적 수정 [K]).

핵심 발견 [A]: 어느 방식이 좋은지는 **프롬프트 난이도에 크게 의존**한다. 그래서 난이도별로 연산을 배분하는 ‘연산 최적’ 전략을 제안했고, best-of-N 대비 4배 이상의 효율 향상을 보고했다. 논문 제목이 말하듯, 일부 설정에서는 추론 연산을 늘리는 쪽이 모델 파라미터를 키우는 것보다 효과적일 수 있다 [A].

### 1.1 s1: 얼마나 단순해도 되는가 [A]
- 난이도·다양성·품질로 고른 1,000개 문제 s1K와 추론 흔적으로 Qwen2.5-32B-Instruct를 미세조정.
- **Budget forcing**: 사고를 짧게 끊을 때는 ‘생각 종료’ 구분자를 넣어 답으로 넘어가게 하고, 늘릴 때는 종료 구분자를 막고 ‘Wait’를 덧붙여 더 탐색하게 한다.
- 결과: s1-32B가 경시대회 수학(MATH, AIME24)에서 o1-preview를 최대 27% 앞서고, 예산 강제로 AIME24가 50%에서 57%로 확장.
- 한계 논의: s1의 단순 스케일링을 분석한 후속 연구와, o1류 모델이 실제로 테스트 시점 스케일링 능력을 갖는지 되묻는 연구가 있다 [A: 제목만, 결론 미검토].

### 1.2 검증기의 역할 [K]
결과만 보는 보상 모델(ORM) 대신 단계별로 채점하는 과정 보상 모델(PRM)이 더 잘 후보를 가려낸다는 연구(Let’s Verify Step by Step, 사람 라벨 PRM800K)와, 사람 라벨 없이 롤아웃으로 단계 보상을 자동 생성하는 Math-Shepherd가 있다. 탐색 기반 추론 시 연산은 **검증기 품질에 의해 상한이 정해진다** [J].

### 1.3 짧게 생각하기
Chain of Draft는 각 단계를 약 5단어 이내로 쓰게 해, CoT와 대등하거나 높은 정확도를 최소 7.6%의 토큰으로 달성한다고 보고했다. 반면 후속 연구들은 어려운 과제·소형 모델·제로샷에서 성능 하락을 지적한다 [A, 2차 출처].

## 2. 말하지 않고 생각하기: 잠재 추론
| 방법 | 아이디어 | 근거 |
|---|---|---|
| **Coconut** | 마지막 은닉 상태를 단어로 디코딩하지 않고 다음 입력으로 되돌린다(‘연속 사고’). 되돌아가기가 많은 계획 과제에서 CoT보다 적은 사고 토큰으로 우수 | [A] |
| 학습 방식 | 학습 과정에서 명시적 추론 단계를 한 단계씩 잠재 사고로 대체하는 **단계적 커리큘럼**(보고된 설정 예: ProsQA는 단계당 4 epoch로 6단계까지, GSM8K는 단계당 3 epoch로 3단계까지) | [A, 2차 출처] |
| **Recurrent Depth** | 순환 블록을 추론 시 더 많이 반복해 토큰을 늘리지 않고 연산을 늘린다. 특별한 학습 데이터·긴 컨텍스트가 필요 없다. 3.5B, 8000억 토큰 규모 개념 증명 | [A] |
| 구조 | **prelude**(입력을 잠재 공간으로 임베딩) → **반복 블록**(잠재 상태를 r번 갱신, **무작위 초기 상태**에서 시작해 초기값에 무관한 정상 상태로 수렴 유도) → **coda**(최종 상태를 다음 토큰 확률로 디코딩). 연산을 늘려도 메모리·컨텍스트 크기가 늘지 않고 반복 횟수는 추론 시 선택 | [A, 본문 기반 2차 출처] |
| **Mixture-of-Recursions** | 파라미터를 공유한 재귀 Transformer에서 토큰마다 재귀 깊이를 라우팅 | [A] |
| **Mixture-of-Depths** | 층마다 top-k 라우터가 처리할 토큰을 고르고 k를 고정해 정적 그래프 유지. 같은 성능에서 순전파 FLOP 감소, 샘플링 최대 약 50% 가속 보고 | [A] |
| **Quiet-STaR** | 매 토큰에서 내부 사고(rationale)를 생성해 미래 텍스트 예측을 돕는다. 제로샷 GSM8K 5.9→10.9%, CommonsenseQA 36.3→47.2% | [A] |
| **Large Concept Models** | 문장 임베딩(SONAR) 공간에서 다음 문장을 예측. 1.6B(1.3T 토큰)·7B(2.7T 토큰) | [A] |
| **BLT** | 다음 바이트 예측 불확실성에 따라 가변 패치 → 어려운 곳에 더 많은 연산 | [A] |

### 2.1 잠재 추론에 대한 후속 평가 [A, 2차 출처]
- **Coconut의 성과 편차**: 한 비교에서 ProsQA 약 97%, ProntoQA 약 99.8%인 반면 GSM8K는 약 34%로 명시적 CoT가 더 강했다. 정리하면 *유연한 탐색형 추론*에는 유리하고 *정밀 계산*에는 불리하며, 학습 커리큘럼에 매우 민감하다는 해석이 나온다. 다른 설정에서는 Coconut이 GSM8K에서 CoT 기준선을 넘지 못했다(10.4% 대 11.0% EM)는 보고도 있다. 셋업이 달라 직접 비교는 금물이다.
- **‘너비 우선 탐색/중첩’ 해석에 대한 이견**: 이론 연구는 연속 사고가 여러 탐색 경로를 중첩 상태로 유지한다고 논증하는 반면, 'Illusion of Superposition?' 연구는 개체 수준 탐침에서 Coconut 모델이 **잠재 토큰 없이도 질문 표현에서 직접 답을 추출**한다고 보고한다(처음부터 학습한 모델에는 중첩 활용 징후가 있음).
- **순환 깊이의 한계**: 깊이 순환 모델(Huginn) 분석은 순환 깊이를 늘려도 이득이 미미하고 추론 단계를 외부로 드러내는 모델에 크게 못 미친다고 보고한다. 고정점에 도달하지 못한 모델은 학습하지 않은 깊이에서 추론이 불안정해진다는 기계적 분석도 있다. 사전학습 모델의 앞 층을 prelude, 뒤 층을 순환 블록·coda로 개조하는 방식이 가장 낫다는 개조(retrofit) 연구도 있다.
- **해석 [J]**: 잠재 추론의 ‘이점’은 과제 유형(탐색 vs 계산)과 학습 방식에 크게 갈리며, 작동 원리에 대한 설명(중첩/BFS)은 아직 합의되지 않았다. 안전 논의(3절)에서 ‘잠재 사고를 해석할 수 있는가’가 중요한데, 작동 원리 자체가 논쟁 중이라는 점이 문제를 더 어렵게 한다.

공통 원리 [J]: 토큰 수와 연산량을 **분리**한다. CoT에서는 연산이 ‘생성된 토큰 수’에 묶여 있지만, 잠재 추론과 적응형 깊이는 토큰당 연산을 가변으로 만든다.

## 3. 핵심 긴장: 능력 ↔ 감시 가능성 [J]
- 사고 사슬 모니터링은 에이전트 코딩 환경에서 보상 해킹을 잡아낼 수 있고, 더 약한 모델이 강한 모델을 감시할 수 있었다. 그러나 CoT 자체에 최적화 압력을 가하면 의도를 숨기는 **난독화**가 학습된다 [A: Baker 등].
- 별도 입장 논문은 CoT가 의도를 들여다보는 드문 창이라고 보고, 모니터링 가능성을 연구·보존하며 개발 결정이 그것에 미치는 영향을 고려하라고 권고한다. 방법이 불완전함(일부 오작동을 놓침)도 인정한다 [A].
- Coconut류 잠재 추론은 사고를 **사람이 읽을 수 없는 연속 상태**로 옮긴다. 능력·효율에서 유리해도 CoT 모니터링이라는 안전 도구를 약화시킬 수 있다 → 구조 선택이 안전 수단에도 영향을 준다는 점은 능력 연구와 안전 연구가 함께 다뤄야 할 문제다 [J, 위 두 [A] 사실에서 추론].
- 추론 모델이 CoT를 통제하기 어렵다는 연구, 난독화를 압박 시험하는 연구가 최근 나왔다 [A: 제목만].

## 4. 비교 [J]
| 축 | 토큰 CoT/탐색 | 잠재 추론 |
|---|---|---|
| 감시·해석 | 읽을 수 있음(완전히 충실하지는 않음) | 어려움 |
| 비용 | 토큰 수에 비례 | 가변 깊이로 절감 가능 |
| 성숙도 | 상용 추론 모델에서 검증됨 | 개념 증명~중간 규모 |
| 학습 | RL/SFT와 결합 쉬움 | 새로운 학습 절차 필요 |
